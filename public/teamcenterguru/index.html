Block release of a Wdg4_Part revision that has no material.
EPM_decision_t Wdg_check_material(EPM_rule_message_t msg)
{
    int n = 0;
    tag_t root = NULLTAG, *targets = NULL;
    EPM_decision_t decision = EPM_go;

    EPM_ask_root_task(msg.task, &root);
    EPM_ask_attachments(root, EPM_target_attachment, &n, &targets);
    for (int i = 0; i < n; i++) {
        char *material = NULL;
        AOM_ask_value_string(targets[i], "wdg4_material", &material);
        if (material == NULL || *material == '\0') decision = EPM_nogo;
        MEM_free(material);
    }
    MEM_free(targets);
    return decision;
}

The problem

Dev, QA and Production drift apart, and nobody can say exactly how.

A Teamcenter site holds thousands of configuration objects spread over a dozen export formats. Promoting a change still means eyeballing XML, keeping spreadsheets and hoping nothing was missed.

    Missed changes reach Production. One access rule or workflow handler out of place can stop engineering work.
  • OPAQUE

  • COST
    Upgrades are slow. Each upgrade starts with weeks of finding out what the site has customized.

    The lifecycle

    From a captured environment to a verified deployment.

    1. CaptureUpload exports or pull them from the server
    2. CompareDiff any two releases or environments
    3. Change noticeRecord problem, affected and solution items
    4. MergeAccept or reject each difference
    5. PackageOrdered import scripts plus a rollback package
    6. DeployRun it; the log records each step
    7. VerifyRe-capture and smoke test the target

    Every release is immutable and content-addressed. Restoring an earlier state is a repoint, not a rebuild.

    Both changedA conflict. Your edits must be merged into the new version.
    Not in targetA feature or template the target no longer ships.
